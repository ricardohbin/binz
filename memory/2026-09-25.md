# 2026-09-25

## Session 1 — Zed extension + tree-sitter grammar

His ask: a Zed extension for binZ, "it seems so sad without syntax highlights".

### What landed (uncommitted, his to commit)

- `editors/tree-sitter-binz/` — tree-sitter grammar (`grammar.js`) mirroring
  `src/lexer.rs` + `src/parser.rs`, deliberately looser than the compiler
  (no imports-first rule, any `@tag`, so half-typed files still highlight).
  `src/parser.c` is generated by `tree-sitter generate` (cli 0.25.10 via npm
  devDependency) and **must be committed**: Zed builds from it, never runs
  generate. Zero LR conflicts. All 13 files in `examples/` parse with no
  ERROR nodes.
- `editors/zed/` — `extension.toml` + `languages/binz/` (`config.toml`,
  `highlights.scm`, `brackets.scm`, `indents.scm`, `outline.scm`). All four
  queries validated with `tree-sitter query`. `tree-sitter.json` points its
  `highlights` at the Zed file, so there is one highlights.scm, not two.
- `editors/README.md` — regenerate/verify/install steps.

### Decisions

- Grammar lives inside the binZ repo, not its own repo; `extension.toml` uses
  `[grammars.binz] path = "editors/tree-sitter-binz"`.
- `rev = "REPLACE_WITH_COMMIT_SHA"`: chicken-and-egg, the grammar has to be
  committed before Zed can fetch it. Local dev: `repository = "file:///..."`.
- `i32 i64 f64 bool str void` are keywords in the grammar (identifiers in the
  real lexer) so they highlight as builtin types.
- Highlight ordering assumes **later pattern wins** in Zed. I believe that is
  Zed's behaviour but did not verify it in a running Zed.

### Not verified

- Never loaded into Zed itself (no GUI here). Verified: grammar generates,
  parser compiles to a native lib, examples parse, queries compile.
- Module calls (`io.print`) highlight `print` as a function but `io` as a
  plain variable: syntactically it is indistinguishable from a struct field.
- No LSP: binZ has no language server, so no diagnostics/go-to-def in Zed.

## Session 1, cont. — first install failed, as predicted

Zed log: `failed to fetch revision REPLACE_WITH_COMMIT_SHA`. The placeholder
was never replaced and nothing was committed yet. Zed clones the grammar into
`editors/zed/grammars/binz` and writes `*.wasm` there, so added
`editors/zed/.gitignore` (`grammars/`, `*.wasm`). Zed log lives at
`~/Library/Logs/Zed/Zed.log`.
