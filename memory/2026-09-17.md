## Session 1 — the test library: `@test`, `binz test`, and `stub`

He opened with the whole shape already decided: "let's create the test lib to
made unit tests. The unit tests must be in the same file, using a 'tag' like
@test above the function. Don't allow unit tests taht starts with the word
'test', it is overlap." And then the hard half: "I want a simple way to
mock/stub used modules - I don't want to pass interfaces and use dependency
injection. but if there's no option we can think about interfaces (binz doesnt
have them yet)."

Branch `feat/improving-string`, clean, identical to `main` at `8d8b04f feat:
importing modules (#6)`. (No `memory/2026-09-16.md` exists — that day was the
modules PR merge and nothing else reached me.)

**The mocking problem had a one-line answer once I read the VM.** Every call
in binZ is already `OP_PUSH_FN <id>` then `OP_CALL`: the callee is a value on
the stack, dispatched by function id. So a stub is a *redirect table* — one
`Vec<u32>` in the VM, one new opcode to write into it — and it replaces the
function rather than the call, which is exactly the property that removes
dependency injection. Nothing is passed in; a call written three files deep
lands in the stub anyway. No interfaces were needed and I did not propose any.

### What I asked him, and what he chose

Three forks, all of which he took as recommended:

1. **Stub form: inline body**, `stub rates.lookup(country: str): f64 { ... }`,
   over `stub rates.lookup = fakeRate;` with a top-level fake. The value form
   needs no new syntax at all (functions are values already), but it puts
   test-only functions in the production file — needing a *second* tag to keep
   them out of the artifact — and one fake per case. The inline body is
   test-only by construction.
2. **`test.calls(math.add)` now**, not "stubs only later". This one matters:
   binZ has no globals and no closures, so a stub body **cannot record
   anything**. Without counting there is no way to assert that something *was*
   called — a stub can only fake the answer. And it is asserted with the same
   `test.equal`, so it adds a noun, not a second way to assert.
3. **`binz test <file>` runs the whole import graph**, so pointing at the entry
   runs the project, and `main` is neither required nor run — which is what
   makes `binz test math.binz` work on a module alone. That closes "no per
   module entry point, so a module cannot be run to test it", flagged
   2026-09-15.

### The design, and the one-way argument for each piece

- **`@test` is the tag, and the name may not repeat it.** His rule. The check
  is case-insensitive on the first four letters, so `testX`, `TestX` and
  `test_x` all stop, and the diagnostic names the spelling to use
  (`testSumsPositives` -> "write `sumsPositives`"). `@test` is the *only* tag;
  `@bench` is refused naming it.
- **A test takes nothing and answers `void`.** `binz test` is the only caller
  and it has nothing to pass, and a test reports by failing so there is no
  result to read.
- **A test is not in the artifact.** `binz build`/`binz run` never declare a
  test, so it cannot be called — by its own file or by an importing one — and
  weighs nothing. The cost is the other half: a test that no longer compiles
  stops `binz test` and nothing else, which is a real hole and is flagged.
- **`test.equal(actual, expected)` is the one assertion**, plus `test.fail` for
  what equality cannot state. No `notEqual`, no `assert`, no `check`: those all
  overlap `equal`, and `MISUSED` now answers each of them with the line to
  write. `equal` compares what `==` compares (so both sides are one type — no
  conversions here either) and prints both sides with `cast<str>`, the one
  formatter the language has.
- **`binz/test` is reachable only from a test body or a stub body.** A program
  never runs one, and in run mode the functions that could are not compiled, so
  a `test.equal` in production code would otherwise ship a trap.
- **Every `stub` goes at the top of its test**, mirroring imports-first. This
  was mine, and it removes a temporal rule: without it, calls before the `stub`
  line would see the real function and calls after would not.
- **The stub's signature is written out in full and must match.** binZ infers
  nothing anywhere else, and a stub that has drifted from the function it fakes
  is the one bug a test library must not hide.
- **One function, one stub per test**; **only a module of this project**, never
  `binz/io` (`io.print` means the same thing in every program); **only a local
  module**, never a function of the file under test.
- **A stub cannot call the function it replaces.** Found by testing it: the
  call lands back in the stub and hangs (ordinary infinite recursion in binZ
  hangs the same way, but this one *looks* like calling through). There is no
  calling through, so it is refused at compile time, `stub_targets` keyed by
  stub function id.
- **Each test runs in a machine of its own**, so stubs are undone for free and
  no test can leave state for the next one. binZ has no globals, so that was
  nearly true already.

### Implementation

- `Tok::Stub`; `@test` is `Tok::At` + `test`, reusing the token `@root` added.
- `FnDef.is_test`, `Stmt::Stub(StubDef)`. `parse_params` factored out, since a
  stub writes the same parameter list a function does.
- `compiler::Mode { Run, Test }` and `FnKind { Plain, Test, StubBody }`. Run
  mode records test *names* (for diagnostics and the duplicate check) but
  declares nothing. Test mode declares each test and, beside it, one hidden
  function per stub — a stub body is an ordinary function that nothing can
  reach by name; `OP_STUB` is the only thing that reaches it.
- `local_member` split into `local_fn_id` + emit, because a `stub` names a
  module member exactly as a call does and wants the same six diagnostics.
- New stdlib module `binz/test`: `fail` is a native, `equal` and `calls` are
  forms (neither type can be written in binZ — `equal` is generic over what
  `==` takes, `calls` over the signature it is handed). `native_indices_are_
  frozen` caught the append immediately, which is the test doing its job.
- `OP_STUB` (one u32 operand, pops a function value). VM: `redirect` is
  allocated only when a stub installs one, `counts` only in a test run, so an
  ordinary program pays nothing for either existing.
- `Module.entry` is now `Option<u32>` and `Module.tests` carries name, file and
  function id; artifact `VERSION` 3 -> 4. **The first bytecode change since the
  stdlib landed** — modules had needed none.
- `binz test` reports file by file: `ok`/`FAIL`, the failing line, and a
  `N passed, M failed` summary; exit 1 if any failed.

113 end-to-end tests (21 new) plus 7 unit. New `examples/orders.binz` +
`examples/modules/rates.binz`, where the real module prints when it runs, so the
example shows a stub taking rather than asserting it. README has a `## Tests`
section with `### Asserting` and `### Stubbing a module`, four new rows in the
guiding-rule table, and a paragraph in `## Implementation`.

### Flagged to him, undecided

- **A test is not type checked by `binz build` or `binz run` at all.** It is
  the price of tests weighing nothing in the artifact, but it means a stale
  test is invisible until someone runs `binz test`.
- **The standard library cannot be stubbed**, so there is no way to capture
  `io.print` output in a test. That is the most likely next ask: natives are
  not bytecode functions, so they would need a second redirect table.
- **A function of the file under test cannot be stubbed** — only a module's.
  Stubbing a same-file helper is a real want; I kept the rule narrow because
  he asked for modules.
- **No setup, no teardown, no filter.** `binz test <file>` runs everything it
  can reach, and there is no way to run one test.
- **`import binz/test;` reserves the word `test` in the file**, the same bite
  as `map` (flagged 2026-09-14) and a likelier variable name.
- **`test.calls` counts every call to the function**, including calls the
  module makes to itself internally, not only the ones the test's code made.
  That is the honest reading of "how many times was it called", but it is not
  the only one.
- **The signature in a mismatch diagnostic prints without parameter names**
  (`function lookup(str): f64`), because `FnSig` does not keep them.
