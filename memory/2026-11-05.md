## Session 2 — `binz/http`, a built-in web server (branch `feat/webserver`)

His ask: "a built in web server. I like in the way express does.
minimalist. for now, just the std lib and some basic routes".

### His call

Asked one question — handler shape. Options: `function(Request): Response`
(return) vs Express `function(Request, Response): void` + `http.send(res,..)`.
**He chose return.** Express's `res.send` cannot be copied: no methods, no
closures.

### Design

- `import binz/http;` members (natives 31-38, appended): `server(): Server`,
  `get/post/put/delete(app, pattern, handler): void`,
  `listen(app, port): Error` (serves forever; answers only on bind failure,
  code 1, or a port outside 0..65535), `text(status, body): Response`,
  `json(status, body): Response` (set Content-Type only).
- `Request` (struct id 1: method, path, params, query, headers, body) and
  `Response` (id 2: status, headers, body) are declared by binZ like `Error`,
  **but named only in a file that imports `binz/http`**; without the import a
  program may declare its own `Request`. Exempt in `struct_in`, so handlers
  live in modules. Maps are `HashMap<str, str>`; request header names are
  lowercased.
- `Server` is a new `Type::Server` (opaque handle, `Obj::Server(Vec<Route>)`),
  also only nameable with the import. No `T{}` default (like fn/ptr).
- Routes: pattern must start `/`; `:name` = one segment; trailing slash and
  `//` collapse; no `?`. **Two routes with the same method and shape trap at
  registration** (one-way rule: the second would be unreachable). First match
  runs. No route for path = 404, path under other method = 405 + `Allow`.
  HEAD = GET without body.
- Handler trap = 500, printed on stderr as `GET /path: runtime error ...`,
  server keeps going. Bad status (outside 100..599) or a header with CR/LF is
  a trap -> 500.
- Wire: `src/http.rs`, std only. One connection at a time, `Connection:
  close`, 10s read timeout, head cap 64KB, body cap 8MB, no chunked bodies
  (501), binds 0.0.0.0.

### Mechanics

- VM re-entry: `Vm.floor`. OP_RET returns from `exec` when
  `frames.len() == floor` (was `is_empty()`). `call_handler` lays Request +
  Response dst on top of `mem`, `enter()` (the OP_CALL Fn body, factored
  out), raises floor, runs `exec`, restores. On trap: truncate frames, stack,
  mem.
- Natives >= `HTTP_FIRST` (31) go to `call_http(&mut self)`; struct-returning
  natives get the sret dst as `args[0]`, write it and push `Ptr(dst)` —
  the compiler already reserved it in `finish_call`. **No artifact VERSION
  bump** (only new native indices, as with `random`).
- CI "Run the examples" now skips files with `^import binz/http;` and echoes
  it; "Test the examples" still covers `examples/http.binz`.
- LSP completion: Request/Response fields and `Server` type offered only
  when http imported (`Outline::builtin_structs`).
- Tests: 148 -> 157 e2e (real sockets: free port, `Served` guard kills the
  child), 30 -> 35 unit. Reinstalled `~/.cargo/bin/binz`.

### Flagged, not decided by him

- `http.text`/`http.json` overlap a `Response{...}` literal with that one
  header — the same bend as `T{}`. Kept because the literal needs a whole
  headers map.
- Single-threaded, one request per connection: a slow handler blocks all.
- Repeated query keys: last wins (a map). Express gives an array.
- `listen` on port 0 binds a random port the program can't learn.
- No middleware, no static files, no `patch`/`options` verbs.
- `req.path` is raw (still percent-encoded); params/query are decoded.
- Binds every interface like Express; localhost-only might be the safer
  default.
