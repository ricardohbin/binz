# 2026-09-10

## Session 1 — binZ v0.1 built from nothing

Started with an empty directory. Asked for: new language "binZ", Rust backend
emitting a bytecode artifact, C/C++/JS-like syntax, primitives + functions,
C-style structs with pointers, `const`/`var`, functions as first-class
citizens, strong typing, compiled, and **one specific way to cast**.

Built the whole pipeline (~3400 lines):

```
src/lexer.rs -> parser.rs -> compiler.rs (type check + emit, single pass)
                                  |
                            bytecode.rs (.binzc + disassembler) -> vm.rs
```

CLI: `binz build | run | exec | dump`. 20 end-to-end tests in `tests/lang.rs`,
all green. Examples: `examples/hello.binz`, `examples/tour.binz`.

### Decisions taken during the build (all derived from "one way to do a thing")

- Mandatory type annotations, no inference. One spelling per declaration.
- Zero implicit conversions, including `i32` -> `i64`. `cast<T>(x)` is the only
  converter, and also the only way to format for `print`.
- No `->` field operator: write `(*p).x`.
- `while` is the only loop. No `+=`, `++`, `--`.
- Conditions parenthesised and must be `bool`. No truthiness.
- Struct literals require every field, in declaration order.
- `print` is the only builtin, and it is an ordinary value of function type.
- Parameters behave like `var` (mutable copies).

Two calls I made without being asked, both flagged to him at the time:
- **No `null`.** `&` only works on `var` places, so every `*T` is valid at
  creation. He did not object, but has not confirmed either.
- **Contextual integer literals** (`var x: i64 = 10;` works, no `10i64`
  suffix). Float literals are always `f64`, so `const x: f64 = 3;` is an error.

### Session 2 — syntax change, same day

He asked for three things:
1. Source extension `.binz` (was `.bz`).
2. `function` keyword instead of `fn`.
3. Return type without the arrow.

Applied as `function name(params): T`, using `:` because that is already how
every other annotation introduces a type. Carried it into type position too:
`function(i64, i64): i64` is the function type. Renamed the artifact `.bzc` ->
`.binzc` for consistency, and told him it was my call to reverse if unwanted.

Kept `fn` and `->` as reserved tokens purely so the old spelling produces a
pointed diagnostic instead of "unknown name". He has not said whether to keep
them long-term.
