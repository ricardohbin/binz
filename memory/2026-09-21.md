## Session 1 — block scope, and no shadowing

Branch `feat/local-scope-vars`, clean and identical to main at
`680b9d4 fix: little adjust in ci.yaml (#9)`.

His ask, in two messages: isolate a scope so every variable created inside it
is removed at the end — useful with `while`, since `while` is the only loop —
written as

    {
      var i = 0;
      while (i <= 10) {}
    }

and then: **redeclaring a name that exists in an outer scope must not
compile.**

### Half of it already existed

`Stmt::Nested(Block, Span)` and the parser's `Tok::LBrace` arm have been there
since `0cb9a12` (first commit). `compile_block` already pushes a scope, and
already does `let mark = self.next_slot; ... self.next_slot = mark;` — so the
frame slots a block used are handed straight back and the next block reuses
them. A bare block was always a scope; it was just undocumented and unexercised
by any test or example.

So the work was the second half, plus making the first half visible.

### What shadowing actually cost (measured, not argued)

Before the change I ran this:

    var i: i32 = 0;
    {
      var j: i32 = 5;
      while (i <= 3) {
        var i: i32 = 99;   // compiled fine
        io.print(cast<str>(j));
        i = i + 1;         // increments the inner one
      }
    }

It compiled and printed `5` forever. The inner `i` is re-created at 99 on every
iteration, `i = i + 1` hits the inner one, the outer `i` never moves. That is
the whole case for the rule, in one program: the loop's own counter was
unreachable from inside the loop body.

### The change

One block in `declare` (`src/compiler.rs`). It already rejected a redeclaration
in the *innermost* scope; now, after that check:

    if self.scopes.iter().rev().skip(1).any(|sc| sc.iter().any(|l| l.name == name)) {
        "`i` is already declared in an enclosing scope, and binZ has no shadowing"
    }

`.skip(1)` is what keeps the two messages apart — same scope keeps the old
"already declared in this scope". Parameters live in `scopes[0]`, so a block
that redeclares a parameter is caught by the same line, no extra code.

Nothing in the VM, bytecode, artifact or parser changed. It is a compile-time
rule only.

In `tests/lang.rs`:

- `a_block_is_a_scope_of_its_own` — a block-scoped loop summing 0..3, then a

### Docs and the example

  block form, "the frame slots are handed back at the brace, so it costs
