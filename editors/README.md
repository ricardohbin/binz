# Editor support

- `tree-sitter-binz/` — the tree-sitter grammar. `src/` is generated by
  `tree-sitter generate` and is committed, because editors build straight
  from `src/parser.c`.
- `zed/` — the Zed extension. It uses the grammar above, and starts the
  language server below.

## The language server

`binz lsp` speaks LSP over stdin/stdout. It offers:

- **completion** — a module's members after `io.` / `math.`, a struct's
  fields after `p.` / `l.from.` / `(*p).`, the locals alive at the cursor,
  the file's functions and structs, types after `:` and inside `cast<...>`,
  tags after `@`, and `binz/...` / `@root/...` paths inside an `import`;
- **diagnostics** — the compiler's first error, run as `binz test` would, so
  a module with no `main` is checked and so is every `@test`.

`@root` is guessed per file: the nearest directory, upwards from the file,
under which all of its `@root/...` imports exist.

Any editor with an LSP client can run it: the command is `binz lsp`.

## Changing the grammar

```sh
cd editors/tree-sitter-binz
npm install
npx tree-sitter generate
npx tree-sitter parse --quiet --stat ../../examples/*.binz ../../examples/modules/**/*.binz
npx tree-sitter query ../zed/languages/binz/highlights.scm ../../examples/tour.binz
```

The grammar mirrors `src/lexer.rs` and `src/parser.rs`. A new keyword or
construct there needs a matching rule in `grammar.js` and, usually, a line in
`zed/languages/binz/highlights.scm`.

## Installing the Zed extension locally

1. Commit the grammar (including `src/`), then put that commit's SHA in
   `zed/extension.toml` under `[grammars.binz] rev`. For local work, set
   `repository` there to `file:///path/to/this/checkout`.
2. Put `binz` on your `PATH` (`cargo install --path .` from the repo root),
   or point Zed at a build in `settings.json`:
   `"lsp": { "binz": { "binary": { "path": "/path/to/target/debug/binz" } } }`.
   Zed needs `rustup` to compile the extension to WebAssembly.
3. In Zed: command palette → `zed: install dev extension` → pick `editors/zed`.
4. Open any `.binz` file.

After changing the grammar, commit again, bump `rev`, and run
`zed: rebuild dev extension`. Errors show up in `zed: open log`.
